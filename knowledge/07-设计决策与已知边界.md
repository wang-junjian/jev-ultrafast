# 07 · 设计决策与已知边界

> 本文以 ADR（架构决策记录）的风格记录"为什么这么做"，以及这个 MVP 明确**不做**什么。理解边界能避免你在错误的方向上投入。

## 一、关键设计决策

### D1：选择题代替生成式输出

**决策**：模型只从观测到的元素/操作/选项索引中选择；唯一生成文本的地方是填值小 LLM，且输出被严格校验为 `{"text": "..."}`。

**理由**：把模型输出空间压到有限集合，执行层才能把每个输出映射回真实 DOM 节点，从根本上杜绝"幻觉选择器/坐标/JS"（`docs/design.md` 第 1 节；`README.md` "Model output never becomes selectors..."）。

**代价**：动作空间覆盖不了的交互（拖拽、键盘控件、iframe 内控件）策略无法表达——见边界 B2。

### D2：一次请求扇出 operation + 全部目标头

**决策**：TypeSafe 的 fan-out 模式——同一请求里问"做哪个操作"和"每个操作分别选谁"，只消费与所选操作匹配的目标头。

**理由**：两次串行调用 = 两次网络往返，是延迟大头；推测性目标头之间互不可见，天然防止"CLICK 操作拿了 TYPE_TEXT 的目标"这类串扰（`model.py:125-130` 的消费规则 + `validate_choice`）。

**代价**：目标头数量随可用操作数增长（最多 3 个），无用头的答案被丢弃；无效头答案必须整体拒绝（测试锁死）。

### D3：语义指纹而非 DOM 变更计数

**决策**：新鲜度用 marker（整页语义）和 page_key+guard（点击/选择的精细语义）比较，且守卫按"作用域"设计——无关区域的可见更新不失效决策。

**理由**：页面背景轮播、计数器跳动这类无关变更极常见，整页指纹会导致频繁作废和重复预测；而对点击真正重要的（目标自身状态、邻近表单上下文、URL/视口/表单值）全部纳入守卫（`browser.py:88-98`、`snapshot.js:44-54`）。

**代价**：这是实用启发式，不是正确性证明——`docs/design.md` 原话："Scoped guards intentionally permit unrelated visible content to change; this is a practical heuristic, not proof that arbitrary page changes are irrelevant to the goal."

### D4：先记执行、再观察；决策一次性消费

**决策**：执行一旦完成立即落 history，之后的观察失败（如导航中断）不回滚记录；决策在任何变更/模型调用前清空。

**理由**：浏览器是并发世界，"执行了但观察失败"和"决策过期"都必须是安全状态。两条规则分别由 `test_stale_observation_preserves_executed_action` 和 `test_stale_decision_is_consumed_before_any_mutation` 锁死。

### D5：几何永远在执行前重读

**决策**：快照里的 rect 只用于展示和命中测试参考；真正输入前用 `getBoundingClientRect()` 重新取坐标并做 `elementFromPoint` 遮挡检测。

**理由**：动画/布局变化在"观察→决策→执行"的几十到几百毫秒里几乎必然发生；重读几何让"移动的目标"不需要新一轮模型调用（check_guards.py 第一条断言）。

### D6：DONE 不是成功的证据

**决策**：模型的 DONE 只改变状态；任务是否成功由**独立检查**判定（`examples/flights.py:18-38` 对最终 URL/字段值/结果列表逐项断言）。

**理由**："A DONE choice is not proof of success"（AGENTS.md）——有效动作仍可能是错误的（`docs/design.md` 边界一节）。AGENTS.md 同样要求"独立验证最终 outcomes"。

### D7：截图在默认循环之外

**决策**：库调用默认无截图（`Agent(screenshots=False)`）；截图仅服务检查器和录制。

**理由**：截图是 page 字典里最大的字段，不进 fingerprint、不进模型上下文；"No screenshots in the default agent loop" 是 README 的卖点之一。检查器的标注数字是事后渲染叠加，不参与驱动（`README.md` "The screenshot renderer adds labels afterward"）。

## 二、已知边界（README + design.md 明示）

### B1：数量与资源
- 60 动作 / 120 决策请求预算；250 动作候选上限（截断的候选不可选）。
- 检查器仅回环（Host/Origin/token 校验、步骤串行化）；标签页共享用户现有 Chrome profile。

### B2：页面能力
- DOM 读取覆盖常见 HTML/ARIA 控件，**不是**完整 accessible-name 规范。
- Shadow roots、frames、canvas、文件上传、弹出新标签页、嵌套滚动、任意键盘交互：不在 MVP 范围内，遇到即可能 BLOCKED。

### B3：可靠性
- "策略是通用的，但两个网站不能证明广泛可靠性"（`docs/design.md`）。性能数字来自单一任务的三次重复。
- 守卫是启发式；合法但错误的动作仍会发生——必须有外部验证兜底。

### B4：文本助手
- 值必须由小 LLM 生成，缺 `TEXT_MODEL_API_KEY` 直接失败而不是猜值。
- 输出契约：恰好一个 `text` 键、≤2000 字符；`{"text": null}` 也算失败。

## 三、演进历史（design.md "What changed after the first demo"）

1. 初版用 **5 个人工准备的步骤 + 复制引号字符串**——只证明了有限选择执行，没证明任务分解和文本生成。
2. 现行策略移除捷径，全程使用原始目标；扁平选择/lookahead 结构被 operation/target 分布取代。
3. 审计发现"每个 INPUT 都可编辑"会误判复选框——可编辑性改由**角色**决定。

这段历史的价值：它说明了本项目的迭代方向是"**每一步都从模型能力里拿掉一点自由度，换成可验证的结构**"。后续开发建议延续这个方向，而不是加回生成自由度。

## 五、术语表

| 术语 | 含义 |
| --- | --- |
| **动作空间（action space）** | 一次观察后模型可选的全部操作+目标的有限集合 |
| **扇出（fan-out）** | 一个请求内并行提问多个问题头，只消费答案所需的头 |
| **目标头（target head）** | 形如 `click_target` 的选择题："假设做 CLICK，选哪个元素" |
| **元素索引** | 模型可见的从 1 开始的编号；`index:option` 是下拉选项编码 |
| **node id** | snapshot.js 给 DOM 节点的代码持有整数 id（WeakMap/Map），模型不可见、不可伪造 |
| **marker / page_key / guards** | 新鲜度三件套：整页语义指纹 / 精细基准 / 每节点守卫快照 |
| **陈旧（Stale）** | 决策所依据的页面状态已不再成立；决策作废但无副作用 |
| **守卫（guard）** | 执行前对页面新鲜度、目标可用性、遮挡的逐项复核 |
| **检查器（inspector）** | `uv run jev` 启动的本地演示/调试 UI |
| **文本助手（text helper）** | 为 fill 动作生成字段值的小 LLM |
