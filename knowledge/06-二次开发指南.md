# 06 · 二次开发指南

> 目标：让你拿到一个改动需求时，知道该动哪些文件、遵守哪些契约、用什么验证。先跑通环境，再按菜谱改。

## 零、开发环境速通

```bash
uv sync                          # 安装依赖（含 browser-harness）
cp .env.example .env             # 填入 TYPESAFE_API_KEY 和 TEXT_MODEL_API_KEY
uv run pytest                    # 离线契约测试（不花钱，必须先全绿）
node --check jev_ultrafast/static/app.js
node --check jev_ultrafast/snapshot.js
uv run ruff check .
uv run python scripts/check_guards.py   # 本地真实浏览器守卫回归（无模型调用）
uv run jev                       # 启动检查器 → http://127.0.0.1:8766
```

五件套（ruff / pytest / 两个 node --check / uv build）是 AGENTS.md 规定的提交前检查。

## 一、常见改动菜谱

### 1. 调模型行为（最频繁）

| 需求 | 改哪 | 注意 |
| --- | --- | --- |
| 改"下一步"策略（如允许更多 WAIT） | `questions.py` 的 `NEXT_ACTION` | 同时影响 operation 和所有目标头；改完跑 `pytest`，`test_target_head_receives_control_state_and_full_next_step_rules` 会锁规则传递 |
| 改填值风格/禁填某类信息 | `questions.py` 的 `TEXT_VALUE` | 输出契约"恰好一个 text 键"不能松 |
| 换文本模型 | 环境变量 `TEXT_MODEL_BASE_URL` / `TEXT_MODEL` / `TEXT_MODEL_REASONING` | `model.py:166-168` 对不同服务商的 reasoning 开关逻辑要匹配 |
| 换 TypeSafe 模型 | 环境变量 `TYPESAFE_MODEL` | 默认 `jev-latest` |

### 2. 新增一个动作种类（如 DRAG / HOVER）

需要动的文件（缺一不可）：

1. `snapshot.js`：产出新 `kind` 的 action（含 `node`、`rect` 等基础字段）；
2. `model.py:51`：operations 映射加条目；`model.py:83-87`：给操作加一句人类可读描述；
3. `browser.py` 的 `browser_operation` act 分支（L135-186）：写执行逻辑，**执行前必须重新解析几何**；
4. `tests/test_agent.py`：补契约测试（非法答案拒绝、动作映射正确）；
5. 如影响动作总数，`snapshot.js:99` 的 250 上限语义保持不变。

如果新 kind 不该是"元素操作"（像 wait/scroll 一样是全局操作），参考 `snapshot.js:102-104` 的追加方式，它会自动走 `controls` 分支（`model.py:54-55`），不用改 operations 映射。

### 3. 新增检查器场景（travel/research 那样的离线演示）

1. `jev_ultrafast/static/fixture.html`：加场景页面（当前 fixtures 是纯静态 + 少量 JS）；
2. `demo.py:47-48`：scenario 白名单加名字；
3. `static/app.js:6-11`：加默认 goal 文案；
4. 场景必须**不依赖外网**（检查器场景跑在 127.0.0.1，flights 是唯一联网场景）。

### 4. 调整预算/上限

| 需求 | 位置 |
| --- | --- |
| 动作步数上限 | `questions.py:26` `MAX_STEPS`（决策请求预算是它的 2 倍，agent.py:75 自动联动） |
| 动作候选上限 | `snapshot.js:99`（250） |
| 页面文本上限 | `snapshot.js:92`（6000，注意 model.py:155 的字段上下文也切到 6000） |
| 文本值长度上限 | `model.py:190`（2000） |
| 初始加载超时 | `browser.py:29`（15 s） |
| 模型超时/重试 | `model.py:12, 21-23`（25 s；429/529/503 指数退避共 3 次） |

### 5. 改守卫行为（高危）

`fresh()` 的两种守卫（`browser.py:88-98`）和 `snapshot.js` 的 marker/guards 构成安全网：守卫变松 → 陈旧决策可能落在已变化的页面上；变紧 → 无关变更频繁使决策作废、循环变慢。改法：

- 加守卫维度：在 `cache.guard`（`snapshot.js:47-54`）数组里加元素，`browser.py:97` 的比对会自动带上（两边都是同一份代码生成的）。
- 改完后**必须**跑 `scripts/check_guards.py`：它逐项断言"什么该使决策失效、什么不该"（移动目标不失效、覆盖层必须拦截、无关离屏文本不失效、表单值/标签/禁用态失效……）。
- 相关 pytest：`test_fingerprint_tracks_values_and_identity_not_screenshots`。

### 6. 给 Agent 加新命令

`command()`（`agent.py:52`）是扩展点：加 `elif name == ...` 分支，返回 `self.snapshot()`。前端在 `app.js` 用 `call("名字")` 即可对接，记得检查器的 409 锁（`demo.py:111`）会自动串行化。

## 二、行为约束（AGENTS.md 项目规约摘要）

- 输入是**一个自然语言目标**，不要往策略里加站点专属计划或硬编码字段值。
- 目标必须映射到**观测到的元素**；绝不允许模型产出选择器或可执行代码（这条已被架构保证，新增代码时别破坏它）。
- **不重试浏览器变更**：执行失败（StalePage 等）只重新观察+决策，不原样重放。
- 凭证只在服务端（.env），测试不得调用付费 API（pytest 全 mock；live 示例才花钱）。
- 示例、README 声明、原始证据、模型调用次数要保持一致——改性能数字时 docs/performance.md 一起改。
- 不主动 commit/push。

## 三、验证矩阵：什么改动配什么验证

| 改动类型 | pytest | check_guards | 线上示例 | 检查器 |
| --- | --- | --- | --- | --- |
| 提示词 | ✅ 规则传递测试 | — | 建议 flights | ✅ |
| model.py 校验逻辑 | ✅ | — | — | — |
| snapshot.js 动作生成 | ✅（契约） | ✅（真实控件矩阵） | — | ✅ |
| browser.py 守卫/执行 | ✅ | ✅（必跑） | 建议 | ✅ |
| 新场景/前端 | — | — | — | ✅ |
| 性能相关 | — | — | ✅ measure | — |

录屏相关工作流：`scripts/record_flights.py <dir>` 录原始时间戳 → `scripts/render_demo.py <dir>` 渲染 1× 视频（裁掉 Google 账号条）。凭证和原始 trace 已在 .gitignore。

## 四、调试技巧

- **看模型实际看到了什么**：检查器右侧 "model-state" 面板，数据源是 `decision.request`（`app.js:136-145`）。
- **看一次运行的完整轨迹**：`examples/flights.py --output <dir>` 会落 `state.json`（含全部 history/decisions/page）。
- **无模型调用地调试浏览器层**：`scripts/check_guards.py` 和 `Browser` 直接对 `data:text/html` 页面操作（见 check_guards.py 开头）。
- **怀疑守卫误伤**：先确认是哪种守卫（marker 整页 vs page_key+guard 精细），再对照 `snapshot.js:44-54` 的构成逐项排查。
- 检查器里用 **Choose next / Execute** 单步可以把"预测"和"执行"拆开，定位问题在哪半边。
